use ai.core
use data.core
use agent.core
use llm.core

task SmartAgent:
    dataset = load_csv("data/readings.csv", target: "fault") -> auto_hardware
    model = classifier(in: 8, classes: 4) -> optimize(speed: max)
    while accuracy < 0.9 max_iters(4):
        train model on dataset(epochs: 2) -> self_heal
    remember("best_acc", accuracy)
    let brief = "Final accuracy: " + str(accuracy)
    let reply = ask llm(brief) -> model("gpt-4o-mini")
    log reply
    export model -> "agent.ae.bin"

You declare. It compiles.

Aether lowers your intent graph to standalone, multi-threaded C99 — fused kernels, adaptive BLAS threading, HTTP servers, LLM clients — then invokes gcc/clang/MSVC. The binary that runs is machine code. No interpreter ships with your agent.

Errors are contracts, not crashes.

Every diagnostic carries a stable code, a hint, and a fix_patch unified diff. Agents apply the patch, re-check, and continue — no human keystrokes. The aether mcp server exposes check / fix / compile / run / spec / bench to any MCP client.

Up and running in 60 seconds.

  1. Clone the compiler.
    git clone https://github.com/aether-ai-lang/aether.git && cd aether
  2. Build the standalone binary (optional but recommended).
    python build_standalone.py → dist/aether.exe, zero Python needed afterwards.
  3. Run your first program.
    aether run hello_aether.ae — compiles to C99 and executes the binary.
  4. Serve a model over HTTP.
    aether run examples/serve_ai_api.ae — the binary is the server.
  5. Benchmark it.
    aether bench examples/train_ai_agent.ae

No C compiler? Aether auto-falls back to its bundled Python/NumPy backend — same language, same semantics. GPUs? The dispatch ladder is CUDA → OpenCL → C99 → Python, honestly reported at every rung.

Everything an agent needs. One grammar.

🧠 ai.core

Tensors, MLPs, classifiers, SGD training with self-healing, chunked streaming inference, AEB1 model export.

📊 data.core

Real CSV ingestion, JSON load/save, all compiled to native C99 file I/O.

🌐 web.core

Serve any model as a JSON API from the compiled binary. Winsock2/POSIX, thread-per-connection.

🤖 agent.core

Loops, persistent memory across executions, and LLM-backed multi-step planning.

🔌 llm.core

OpenAI-compatible chat completions from raw C99 sockets (WinHTTP/libcurl), with deterministic mock mode.

⚙️ sys.core

File read/write and JSON field loading — the glue agents need, at machine speed.

Hardware dispatch. Honest at every rung.

$ aether run examples/train_ai_agent.ae
  [device] auto_hardware -> cuda/RTX 3060 | SM 86       ← GPU + nvcc
  [device] auto_hardware -> opencl | ICD loaded         ← OpenCL tier
  [device] auto_hardware -> c/native | 16 threads |     ← AVX-512 + OpenBLAS
           OpenBLAS | discrete-gpu tier | f32

No fake GPU execution. Ever.

When a tier is unavailable — no nvcc, no registered ICD, no compiler — Aether says so in the telemetry and JSON note field, then dispatches to the next tier. The same program runs everywhere; the hardware report is always truthful.
